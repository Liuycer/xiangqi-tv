# Phase 11 性能优化报告

测试日期：2026-08-18  
测试设备：Tmall MagicBox_M_30_F，API 29，32 位，WebView 74

## 结论

Phase 11 已解决 AI 严重超过时间预算的问题，并提升了相同时间内的搜索深度。三档 AI 的最终误差为 4～16ms，困难档在更短时间内从完整深度 D2 提升至 D3。

棋盘改为按交叉点视觉状态增量更新，AI Worker 在完成一回合后释放，降低了界面更新耗时和 AI 回合后的常驻内存。APK 仍保持约 1.31MB，不包含网络权限或原生库。

## AI 前后对比

测试局面与 Phase 10 一致：玩家执红，右侧车前进一步，等待黑方 AI 应手。

| 难度 | 时间预算 | Phase 10 | Phase 11 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 简单 | 350ms | D2 / 2296ms / 227节点 | D1 / 366ms / 153节点 | 耗时降低约 84%，符合深度 1～2 定位 |
| 普通 | 1100ms | D2 / 2432ms / 256节点 | D2 / 1104ms / 289节点 | 耗时降低约 55%，预算误差 4ms |
| 困难 | 2800ms | D2 / 4329ms / 512节点 | D3 / 2805ms / 2316节点 | 耗时降低约 35%，节点数约 4.5 倍 |

主要优化：

- 截止时间从每 256 节点检查一次改为每个节点检查。
- 深度为 0 的叶子节点直接执行局面评估，不再生成整套合法走法。
- 每轮迭代加深复用根节点合法走法。
- `applyMove` 从查找、过滤、映射三段数组遍历合并为单次遍历。
- 新增零预算回归测试，保证首个搜索节点就能响应超时。

搜索仍使用 Web Worker，因此 AI 高 CPU 计算不会直接阻塞 Vue 主线程。

## 内存

| 指标 | Phase 10 | Phase 11 最终候选 |
| --- | ---: | ---: |
| 空闲 Total PSS | 101814KB | 104369KB |
| 困难 AI 后 Total PSS | 112729KB | 111197KB |
| 单回合增量 | 10915KB | 6828KB |

不同启动轮次的系统共享页会造成绝对 PSS 波动，因此重点比较同一轮测试的增量。AI 回合增量下降约 37%。实现方式是在没有待处理请求时终止 Worker，使搜索临时堆可以回收；下一回合按需重新创建 Worker。

棋盘状态中的未移动棋子现在复用已冻结对象，不再在每一步复制全部棋子。

## Vue 与渲染

- 90 个棋盘交叉点预先生成视觉状态位掩码，并通过 `v-memo` 只更新状态真正变化的节点。
- 32 个棋子按行列位置使用 `v-memo`，未移动棋子跳过组件更新。
- 遥控器只移动光标时，不再替换未改变的棋局快照。
- 合法落点由重复线性查找改为坐标 Map 查询。
- 缩小棋子、选择框、合法落点和将军标记的模糊阴影半径。

最终遥控器/困难 AI 样本：

| 指标 | Phase 10 | Phase 11 |
| --- | ---: | ---: |
| P50 帧耗时 | 46ms | 40ms |
| P90 帧耗时 | 250ms | 250ms |
| Slow UI thread | 1 | 1 |
| High input latency | 0 | 0 |

`gfxinfo` 每轮只有约 15 帧，并混有 ADB 逐键注入，百分比波动较大，不能作为连续动画帧率。P50 改善约 13%，输入延迟计数保持为 0；电视画面与遥控器操作已再次目视确认。
