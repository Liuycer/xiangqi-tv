# Phase 35 同步失败管理与档案恢复

## 同步失败管理

Phase 30 已能把不可恢复的 4xx 写入本机隔离区，但用户看不到这些诊断。Phase 35 将隔离记录按 `gameId` 聚合，只暴露失败时间、HTTP 状态、操作种类和数量，不在界面展示请求正文。

- 历史面板仅在存在失败记录时显示“同步异常 N”。
- 弹窗说明这些对局不会自动重试，也不会影响后续对局。
- 支持逐局删除或清空全部本机诊断。
- 删除诊断不伪装成补传，也不改写服务器历史。
- “设置与棋谱”继续只保留落子音效和走子动画。

## 一次性 Profile 恢复码

每个有效 Profile 可由当前所属设备生成形如 `XQ-XXXX-XXXX-XXXX-XXXX` 的恢复码。字符集排除易混淆字符，总随机量为 80-bit。

- 恢复码只在生成响应中返回一次；SQLite 仅保存带域分隔的 SHA-256 摘要和生成时间。
- 每次生成新码都会覆盖旧摘要，因此旧码立即失效。
- 新设备输入后，服务器在同一事务中更新 `device_id` 并清除摘要；码无法再次使用。
- 段位、评级、历史、逐手分析和自适应进度都沿用原 Profile ID，无需复制业务数据。
- 归档 Profile 会清除恢复摘要；归档档案不能恢复。
- 目标设备已有 6 个有效 Profile 时拒绝转移，原设备所有权保持不变。
