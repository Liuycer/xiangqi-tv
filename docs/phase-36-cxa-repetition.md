# Phase 36 中国象棋协会循环裁定

## 规则基准

本阶段以中国象棋协会审定的《象棋竞赛规则（2020版）》第 23～26 条为准，
不采用 WXF / Asian Rule。程序采用三次重复局面作为自动审核触发点，并按以下
性质逐着重放：

- 将：走子后直接将军；
- 杀：新产生、可由连续将军强制完成的杀势；
- 捉：新产生可净得子的直接或联合攻击；
- 闲：不属于将、杀、捉，包括正常兑、献、拦、跟。

单方每一着均属于将、杀、捉之一时，覆盖长将、长杀、长捉、一将一杀、
一将一捉和一杀一捉等禁止着法。单方长将依据 25.1 优先判负；只有一方为
禁止着法时该方判负；双方均为允许着法，或双方均为禁止着法且无法证明
26.9.1～3 的单方责任时，按 25.2 / 26.9.4 判和。

参考文本：

- [第 23 条：待判局面的裁定](https://cnchess.net/rules/ChapterFiveSection23.html)
- [第 24 条：术语解释](https://cnchess.net/rules/ChapterSixSection24.html)
- [第 25 条：棋例总纲](https://cnchess.net/rules/ChapterSixSection25.html)
- [第 26 条：棋例通则](https://cnchess.net/rules/ChapterSixSection26.html)

## 自动裁定边界

中规中的部分“杀”、多步交换价值、自毙和少根子案例依赖较深计算，规则原文
本身也保留裁判解释空间。为避免电视游戏错误判负，本实现只在程序能够证明时
标记杀或捉：杀势最多验证三次连续将军回合；捉子要求目标无有效反吃，或弱子
换强子能产生明确子力收益。帅将、兵卒自身的追捉不计为捉，但走动后由其他子
新产生的捉仍会被识别；未过河兵卒不作为得子目标。

超出上述证明范围的复杂棋例保守按“闲”处理。这意味着普通对局不会因启发式
猜测被错误判负，但极少数需要现场裁判分析的职业棋例可能仍判和。此边界比把
所有攻击都视为长捉更符合用户侧安全性，也在 UI 和 README 中明确说明。

## 前后端一致性

- 客户端在第三次重复时从棋盘快照重新计算走子性质；非长将禁止循环显示
  “禁止着法判负”，并细分长杀、长捉或混合攻击性循环。
- 服务端为每枚棋子分配仅用于重放的稳定 ID，以相同分类独立复核上传棋谱；
  `prohibited-repetition` 终局不能由客户端伪造。
- 原有 `perpetual-check` 与 `repetition_draw` 终局字符串保持兼容。
