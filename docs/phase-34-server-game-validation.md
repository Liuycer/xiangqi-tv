# Phase 34 服务端棋谱与终局校验

## 目标

历史服务此前只检查 UCI 字符串格式，并相信客户端提交的 `currentPlayer`、`result` 和 `termination`。Phase 34 在云端增加独立规则边界，使篡改、损坏或客户端 bug 产生的棋谱不能进入历史、赛后分析和评级流程。

## 实现

- 从完整中国象棋 FEN 解析 10×9 棋盘和行棋方。
- 每手按 UCI 坐标逐步重放，验证轮次、起止点、同色占位和禁止直接吃将。
- 覆盖车、炮、马、象、士、将、兵全部移动规则，包括炮架、蹩马腿、塞象眼、象不过河、士将不出九宫和兵的过河方向。
- 每手落子后验证本方不被将军，并禁止将帅在同一路直接照面。
- 每步重新计算将军、将死、困毙、三次重复和单方连续长将结果；终局后拒绝继续追加着法。
- snapshot 的 `currentPlayer` 必须与重放结果一致。
- completed 只接受真实终局，且 `result`、`termination` 必须分别与胜方和终局类型一致；abandoned 仍允许在非终局保存。
- `/move` 与 `/analyze` 在把局面交给 Pikafish 前执行相同的 FEN 与棋谱合法性校验。

## 接口行为

非法棋谱、伪造终局或行棋方不一致统一返回 HTTP 422，并且不会写入 `games` / `game_moves`。找不到对局仍返回 404，设备与 Profile 归属校验顺序保持不变。

API 版本由 0.4.1 升级为 0.5.0。
