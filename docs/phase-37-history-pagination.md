# Phase 37 历史对局分页修复

## 问题

历史接口每页最多返回 20 局，但客户端只读取第一页。Profile 拥有超过 20 局
历史时，列表仍能正常打开，却无法看到第 21 局及更早的记录。

## 修复

- 首次打开历史仍只读取最新 20 局，避免一次请求和渲染全部记录。
- 列表末尾在仍有数据时显示“加载更多（已加载 / 总数）”，每次继续读取 20 局。
- 根据服务端返回的 `total`、`offset` 和实际条目数推进游标；合并时按对局 ID
  去重，同时保持从新到旧的原始顺序。
- 鼠标可以直接点击“加载更多”。遥控器向下移动到列表末尾后会聚焦该按钮，
  按确认键加载下一页、自动选择新一页第一局并滚动到可见位置。
- 遥控器快速扫过历史条目时，立即更新选中态，但将详情请求延迟 300ms；只有
  最终停留的对局会读取详情，避免连续请求触发 Nginx 429 限流。
- 分页响应增加运行时结构校验，`total`、`offset` 或 `items` 格式错误时不会
  污染现有列表。

本阶段只修改客户端。现有服务端分页接口已经支持 `limit=20&offset=N`，无需
变更或重新部署；API 继续使用当前 IP 地址访问。
