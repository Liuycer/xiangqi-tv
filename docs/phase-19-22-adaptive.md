# Phase 19–22 对局数据与自适应难度

## Phase 19：对局生命周期

- 客户端为每盘棋生成稳定的 `clientGameId`，开始、快照和结束操作进入独立本地 outbox。
- 网络中断时不阻塞棋盘，恢复后按顺序补传；快照可合并，结束事件不会被旧快照覆盖。
- 服务端 SQLite 使用 WAL，保存玩家、对局和逐手 UCI 记录，创建与结束接口均可幂等重试。
- 同一玩家创建新局时，服务器自动把遗留活动局标记为“被新局替代”，覆盖断电、崩溃或系统强杀无法发送结束事件的情况。

## Phase 20：赛后分析

- 完成的人机对局进入持久分析队列，服务重启后可从逐手 checkpoint 继续。
- 后台 Pikafish 只分析红方落子；实时走棋和局面分析到达时，后台任务主动让出单引擎资源。
- 每手保存最佳着法、前后评分、损失、分类、深度、节点和耗时。

## Phase 21：影子评级

- 内部使用 A0–A7 八级映射，外部既有固定难度不被改变。
- 不完整、过短、悔棋、改设置或使用本地回退的对局被记录但不参与评级。
- Elo 更新和评级事件幂等；先在影子数据中计算推荐等级，便于核对规则。

## Phase 22：自适应启用

- 操作区新增“自适应”，服务器等级决定本地/云端、搜索深度和是否拟人化。
- 满足有效盘数与滚动得分阈值后，每次最多升降一级，避免难度跳变。
- 设置面板可以锁定当前等级或重置水平；服务端功能开关可随时切回影子模式。

各阶段只执行了对应数据流的冒烟测试，最终部署和真机检查统一在 Phase 24 后进行。
