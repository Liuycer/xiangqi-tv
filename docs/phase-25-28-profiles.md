# Phase 25–28 棋手 Profile 排位自适应

## Phase 25：Profile 数据与迁移

- SQLite schema v5 在原 `players` 评级数据上增加设备归属、显示名、头像、软删除和最近使用时间。
- 首次 bootstrap 会把旧客户端的 playerId 无损迁移为“默认棋手”，历史、评分和分析数据不移动。
- 每台设备最多 6 个有效 Profile；不同 deviceId 不能读写对方的档案。
- 新建和重置档案从 A1 / 1050 分起步。

## Phase 26：电视端 Profile 界面

- 每次冷启动先进入“这次是谁来下棋”选择层。
- 支持鼠标操作的选择、新建、改名/换头像、切换、重置和软删除；遥控器可用方向键和 OK 完成选择。
- 弹层使用最大高度与内部滚动，兼容 1080p 与 4K 输出，最多 6 张档案卡不溢出画面。

## Phase 27：只保留排位自适应

- 移除简单/普通/困难/自定义和深度选单，人机对局始终使用当前 Profile 的 A0–A7 等级。
- A0 本地 D2；A1/A2 云端 D3，分别使用强/中等拟人化；A3–A7 为云端 D4/D5/D7/D9/D11。
- 有效对局每次最多升降一级；本地回退、悔棋、过短、本地双人、中途切换或分析不完整的对局不计分。
- 分析功能仍保留快速/标准/深入三档，它们只控制分析时长。

## Phase 28：数据隔离与收尾

- 对局创建、快照、结束、历史列表和详情请求都携带 deviceId + profileId，服务器核验归属。
- 历史列表、逐手回放、赛后 AI 分析和评级事件继续通过 game.player_id 与 Profile 隔离。
- 切换 Profile 时当前对局以 `profile_switched` 标记为未完成，然后为新棋手开始新局。
- 旧 API 保留一个版本的无 deviceId 兼容路径，新 APK 全部使用归属校验路径。
